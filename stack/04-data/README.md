# 04 Data: PostgreSQL, Valkey, event stream

## Role
- **Postgres** holds the durable record: users, shows, answers, the ledger, claims, KYC references and the audit trail.
- **Valkey** holds live state at 30k+ writes per second.
- **The event stream** feeds risk scoring and analytics.

## Decision

| Store | Choice | Why |
|---|---|---|
| Durable | **Aurora PostgreSQL 17** (Multi-AZ, Global Database secondary in Ireland), RDS Proxy | Failover is "often < 30 s", and RDS Proxy cuts failover time by up to 66% ([Aurora HA](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Concepts.AuroraHighAvailability.html)) |
| Live state | **ElastiCache for Valkey 9.1**, node-based, cluster mode | 20% cheaper than Redis OSS. Node-based clusters avoid Serverless's 10–12 min scale-up lag ([pricing](https://aws.amazon.com/elasticache/pricing/), [troubleshooting](https://docs.aws.amazon.com/AmazonElastiCache/latest/dg/wwe-troubleshooting.html)) |
| Events | **Kinesis Data Streams → Firehose (JSON → Parquet) → S3 → Athena** (partition projection) | Firehose converts only JSON input to Parquet ([format conversion](https://docs.aws.amazon.com/firehose/latest/dev/record-format-conversion.html)) |

## Best practices

**PostgreSQL**
1. Money is stored as `bigint` minor units plus an ISO 4217 code. Never use float or the `money` type ([PG docs](https://www.postgresql.org/docs/current/datatype-money.html)).
2. **The ledger is double-entry and append-only.** Every transaction must sum to zero. Mistakes are corrected with reversal entries. Each account row carries `balance` and `version`, and every entry stores `prev_balance` and `new_balance` ([Fowler](https://martinfowler.com/eaaDev/AccountingNarrative.html), [Square Books](https://developer.squareup.com/blog/books-an-immutable-double-entry-accounting-database-service/), [pgledger](https://github.com/pgr0ss/pgledger)).
3. `REVOKE UPDATE, DELETE` on `ledger_entries` and `audit_log`. A trigger checks that each transaction balances to zero.
4. Primary keys are UUIDv7 generated by the application. Do not use `nextval`, because sequences pin RDS Proxy sessions.
5. Migrations use goose, run as a one-off ECS task before deploy, expand-then-contract only. **A migration must never take a long lock during a show window** (CI blocks deploys inside show windows).
6. Use sqlc for type-safe queries. Never build SQL with string concatenation.

**Valkey** (key patterns: [docs/research/07](../../docs/research/07-persistence-sourced-values.md))

7. **Hot keys are sharded across slots.** The tally key is `tally:{s:q:N}` with N in 0..63, and each shard uses a different hash tag so the shards land on different slots. Readers sum all shards ([cluster spec](https://valkey.io/topics/cluster-spec/)).
8. Multi-key commands and Lua scripts only operate on keys that share one slot (same hash tag); anything else fails with `CROSSSLOT`.
9. Every key has a TTL. Show keys expire 24 h after `SETTLED`.
10. Valkey state must be rebuildable from durable sources. Never let Valkey be the only copy of something that must persist.

**Kinesis / analytics**

11. The partition key is **user_id**, never show_id. Write with PutRecords in batches of up to 500 and retry the records that failed ([sizing](https://docs.aws.amazon.com/streams/latest/dev/how-do-i-size-a-stream.html)).
12. **An on-demand stream throttles if traffic exceeds 2× its 30-day peak within 15 min.** A show goes from near zero to peak almost instantly, so use **provisioned mode** and re-shard during pre-show scaling, or reserve warm throughput.
13. Firehose partitions S3 data only by `dt/hour/show_id`. The limit is 500 active partitions ([limits](https://docs.aws.amazon.com/firehose/latest/dev/limits.html)).
14. Athena uses partition projection, so no crawlers are needed ([projection](https://docs.aws.amazon.com/athena/latest/ug/partition-projection.html)).

## Rules for this codebase
- Schema: SPEC §6.6. Key design: SPEC §6.7.
- PII columns (`phone_enc`, `iban_enc`) use application-level envelope encryption with KMS. Phone numbers are looked up by HMAC hash.
- Alarm on `DatabaseConnectionsCurrentlySessionPinned`.
